## Shared implementation

`book/_ext/textbook.py` registers the `interactive-demo` directive and produces an HTML host or printable prose. The directive requires static content. An `env-updated` check rejects more than one demo across a lecture's topic pages. Add each future demo kind to the directive registry and shared JavaScript when its lecture is written.

`book/_static/textbook-interactives.js` initializes the demos. Lecture 1 dynamically loads `textbook-3d.mjs`, using locally vendored Three.js r180 and OrbitControls; Lecture 2 retains its local SVG warp explorer. No runtime CDN, account, or Python service is required. Library provenance and MIT license are under `book/_static/vendor/three/`. ESM dependencies use `.mjs` so Jupyter Book does not inject them as classic scripts.

The projection explorer renders genuine 3D geometry: camera body/center, camera axes, a bounded virtual image plane, its corner rays, a world point, and the projection ray/intersection. Empty-space orbit and zoom alter only the inspection view. Dragging the sphere moves it in its fixed world-Z plane; sliders provide equivalent keyboard controls plus point depth, camera translation/yaw, and focal length. A linked 2D image and three calculation cards connect world point, camera coordinates, and pixels. Reset restores both scene parameters and inspection view.

The camera initially uses P=(1,0.5,10), C=(0,0,0), principal point (250,250), f=500 pixels, and a 500×500 image. Positive camera yaw alpha is a camera-to-world Ry(alpha); world-to-camera R=Ry(-alpha), t=-RC. A fixed pixel pitch of 0.004 world-length units/pixel makes the virtual plane's width/height two units and its distance f×0.004. Mesh axes use a proper fixed 180-degree X rotation to map textbook X-right/Y-down/Z-forward coordinates into Three.js's view convention. Projection remains computed in textbook coordinates; the inspection camera never enters the math. Zero/negative camera depth and off-image visibility are distinct. The visible 3D intersection is exactly the camera-ray/virtual-plane intersection, not a separate animation.

The MyST fallback remains visible until initialization succeeds. Missing JavaScript, module-load failure, or unavailable WebGL preserves the full static explanation and its paired vector diagram. Browser printing and LaTeX include the same static material. Layout stacks on phones; native sliders, view buttons, labels, and announced values support keyboard operation. Rendering occurs on changes rather than a continuous animation loop.

The homography explorer uses H with bottom row (p, 0, 1), p in [-0.8, 0.8], and a source square [-1, 1]^2. Every denominator stays positive. Panels are fitted separately, so the labels state that displayed scale differs. Four numbered collinear points test the invariant cross-ratio 4/3. Its paired SVG/PDF static view is regenerated by `scripts/build_interactive_figures.py`.

## Lecture 3 sampling explorer

Implemented next to the pentagon/RANSAC probability application in `lecture03/probability-ransac.md`. The local SVG widget varies inlier percentage (5–95%) and trial count (1–3,000), shows the first 40 four-status hypotheses, counts clean samples in one experiment, and compares the theoretical success probability with 200 simulated experiments. It uses a deterministic seeded generator; “Run another experiment” changes the seed and Reset restores the initial seed and parameters. Numerical substitutions and the 99% budget update live. The model explicitly assumes independent match statuses and nondegenerate clean samples; it is not the exact finite-pool pentagon sampler. Two hundred experiment successes are sampled using the equivalent per-hypothesis Bernoulli probability q=w^4.

This probability exercise uses a sampling display rather than a spatial scene. The complete MyST fallback has three computed cases, interpretation, and a vector probability curve. Native sliders/buttons, announced numeric results, mobile-local diagram scrolling, no-script fallback, and print content use the shared infrastructure. Reproducible checks: `scripts/check_lecture03_math.py`, `scripts/check_lecture03_browser.py`. No remote runtime dependencies were added.

## Lecture 4 stereo explorer

Implemented in `lecture04/stereo.md` using the shared `interactive-demo` host and the local `textbook-stereo.mjs` module. Two aligned cameras at (0,0,0) and (b,0,0) observe P=(b/2,0,Z). Linked 250×200 images have principal point (125,100), square pixels and shared focal length. The 0.02 cm/pixel pitch sizes the actual virtual image planes to 5×4 cm at depth f×0.02 cm. Orange marks the true point/ray, blue the true right ray, purple the perturbed right ray and reconstructed point. An epipolar-plane patch spans the actual camera centers and true point. The model solves the ray intersection using measured disparity d+delta; its visible 3D coordinates agree with the displayed projection equations. Nonpositive measured disparity does not create a false forward reconstruction.

Controls adjust depth, baseline, focal length and signed disparity error. Dragging the true point changes depth while keeping it centered between cameras; orbiting and zooming only inspect the geometry. Reset restores the model and inspection view. A side view and perspective view aid inspection. Marker sizes are schematic and do not enter the math. The default scene is fitted with phone width in mind.

The static MyST explanation includes left/right column values, signed perturbations, exact depths and a sensitivity curve; it remains the PDF/no-JavaScript teaching path. Browser checks independently intersect the two normalized rays and reproject the estimate, verify actual virtual-plane intersections, sweep valid/zero/negative/off-image states, exercise dragging/orbit/zoom/keyboard/reset, and test mobile/no-JS/module failure/no-WebGL/print fallback. No new remote dependencies.
